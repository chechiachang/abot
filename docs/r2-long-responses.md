# Telegram long-response delivery

Telegram's Bot API `sendMessage` text limit is 4096 units after entity parsing. In practice, count UTF-16 code units (the same unit used for Telegram entity offsets), not UTF-8 bytes or Unicode code points: supplementary characters such as emoji count as two. This pathway sends text messages; media caption limits are separate. Because server-side entity parsing/formatting can complicate the effective length, the implementation takes a conservative route and offloads answers above **3500 UTF-16 units**. That leaves 596 units below the API limit for formatting, link/reply decoration, and parsing edge cases. The limit is defined at `internal/telegram/render.go` as `DefaultTelegramOffloadThreshold`.

`telegram.response_inline_threshold` is a separate, configurable inline-display UX preference. It defaults to 1000 and is not the R2 threshold or a Telegram/iOS limit. Responses above this preference still remain inline up to 3500 units; responses above 3500 are offloaded regardless of the preference. The accepted config range is 1–4095 and the setting is also available as `ABOT_TELEGRAM_RESPONSE_INLINE_THRESHOLD`.

Configure private R2 storage with account ID, bucket, optional endpoint/prefix, URL expiry, and maximum response bytes in `config.yaml`. Set `ABOT_TELEGRAM_R2_ACCESS_KEY_ID` and `ABOT_TELEGRAM_R2_SECRET_ACCESS_KEY` via environment secrets; credential fields in YAML are rejected. See `config.example.yaml` and `.env.example`. Use an HTTPS Cloudflare endpoint, private bucket, and a dedicated token scoped to read/write only in this bucket. Presigned URLs grant bearer access until expiry; choose a short expiry appropriate to your content. R2 does not delete objects when links expire: use a bucket lifecycle rule to expire stored response objects.

Defaults when enabled are a 15-minute URL expiry and 5 MiB response limit. Limits are 1 minute–7 days and 1 byte–50 MiB. Objects receive cryptographically random names, are uploaded as UTF-8 plain text with server-side encryption, and are never logged by the application. When R2 is not configured, the existing Morsel publisher fallback is used; its configured failure/disabled behavior remains unchanged.
