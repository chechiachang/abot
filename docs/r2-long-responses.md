# Telegram long-response delivery

Telegram's Bot API `sendMessage` `text` field has a hard maximum of **4096 characters after entity parsing**. This is not 1000. The application counts Unicode code points (`utf8.RuneCountInString`), not UTF-8 bytes; UTF-8 emoji commonly occupy several bytes while counting as a code point. Official source: [Telegram Bot API — sendMessage](https://core.telegram.org/bots/api#sendmessage).

The separate `telegram.response_inline_threshold` setting controls a **mobile-reading UX choice**, not an API limit. Its default is 1000 Unicode code points: responses at or below this threshold are sent inline; longer responses are offloaded to configured private R2 (or the existing Morsel fallback) before reaching Telegram's 4096-character hard maximum. Change it via config or `ABOT_TELEGRAM_RESPONSE_INLINE_THRESHOLD`, but keep it below 4096. The number is a conservative product default, not a Telegram or Apple prescribed limit. Apple's iPhone Human Interface Guidelines emphasize readable typography, hierarchy, and adapting text to device size; they specify no maximum chat-message character count: [Apple HIG — Typography](https://developer.apple.com/design/human-interface-guidelines/typography). Thus there is no authoritative iPhone character threshold; 1000 is an explicit UX decision, distinct from the Bot API's limit.

Configure private R2 storage with account ID, bucket, optional endpoint/prefix, URL expiry, and maximum response bytes in `config.yaml`. Set `ABOT_TELEGRAM_R2_ACCESS_KEY_ID` and `ABOT_TELEGRAM_R2_SECRET_ACCESS_KEY` via environment secrets; credential fields in YAML are rejected. See `config.example.yaml` and `.env.example`. Use an HTTPS Cloudflare endpoint, private bucket, and a dedicated token scoped to read/write only in this bucket. Presigned URLs grant bearer access until expiry; choose a short expiry appropriate to your content. R2 does not delete objects when links expire: use a bucket lifecycle rule to expire stored response objects.

Defaults when enabled are a 15-minute URL expiry and 5 MiB response limit. Limits are 1 minute–7 days and 1 byte–50 MiB. Objects receive cryptographically random names, are uploaded as UTF-8 plain text with server-side encryption, and are never logged by the application.
